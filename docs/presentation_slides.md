## SLIDE 03 — 사업 배경 ①: 왜 유가인가

**헤드라인**: "유가 1% 변동이 국내 에너지 비용 수천억을 흔든다"

| 항목 | 내용 |
|------|------|
| WTI 일일 거래량 | 약 10억 달러 이상 |
| 연쇄 영향 산업 | 에너지, 물류, 항공, 석유화학, 금융(파생상품) |
| 2026년 실제 변동 | WTI $63 → $112 급등 후 $87 회귀 (5개월 내 약 70% 변동폭) |
| 기업 직접 비용 | 유가 10% 상승 시 항공사 연료비 연간 수백억 원 추가 발생 |
| 에너지 수입 의존도 | 한국은 원유 수입 의존도 99%+, 국제 유가 직접 연동 |

> **발표 스크립트**  
> "국제 유가는 단순한 에너지 가격이 아닙니다. 물류비, 원자재비, 심지어 금리와도 연동되어 있습니다. 특히 2026년은 관세 전쟁과 지정학적 긴장이 겹치면서 5개월 만에 70% 가까운 변동폭이 나타났습니다. 이런 환경에서 하루라도 먼저 리스크를 감지하는 것이 실질적 경제 가치를 만들어냅니다."

**시각 요소**: WTI 2026년 가격 추이 차트 (급등락 구간 하이라이트)

## SLIDE 04 — 사업 배경 ②: 기존 방법의 한계

**헤드라인**: "기존 예측 도구는 블랙스완 앞에서 침묵한다"

| 기존 방법 | 한계점 |
|----------|--------|
| 단순 시계열 (AR/ARIMA) | 뉴스·지정학 이벤트 전혀 반영 불가 |
| 애널리스트 리포트 | 실시간성 없음, 비용 高, 주관적 편향 |
| 선물 내재 변동성 (OVX) | 방향성 정보 없음 — 오를지 내릴지 알 수 없음 |
| 단일 모델 예측 | 시장 레짐 전환(고변동↔저변동) 적응 불가 |
| 뉴스 감성 단독 분석 | 유가 외 잡음 과다, 정량화 기준 없음 |

> **발표 스크립트**  
> "기존 방법들의 공통적인 한계는 세 가지입니다. 첫째, 뉴스나 지정학 이벤트를 수치로 반영하지 못합니다. 둘째, 시장 환경이 바뀌면 모델이 그대로 틀려버립니다. 셋째, 이상 충격—블랙스완—이 발생했을 때 신뢰 구간을 자동으로 조정하는 메커니즘이 없습니다. 저희는 이 세 가지 문제를 동시에 해결하는 방향으로 설계했습니다."

**시각 요소**: 기존 방법 vs 우리 시스템 비교 표

## SLIDE 05 — 프로젝트 목표 & 접근 방향

**4가지 핵심 목표**

| 목표 | 기준 | 달성 여부 |
|------|------|----------|
| D+1~D+7 가격 예측 | MASE < 1.0 (Persistence 대비 우위) | ✅ MASE = 0.602 |
| 리스크 등급 자동 분류 | SURGE / DROP / CAUTION / NORMAL | ✅ 구현 완료 |
| 일일 파이프라인 자동화 | 5분 이내 완료 | ✅ 약 3분 |
| 블랙스완 이벤트 감지 | 관세·지정학 키워드 + 통계적 이상치 | ✅ 구현 완료 |

**접근 방향**
- 다중 데이터 소스 (가격 + 뉴스 + 재고 + 지정학)
- 앙상블 모델 (단일 모델 실패 리스크 분산)
- 레짐 적응형 재훈련 (자동 트리거)
- 운영 자동화 (스케줄러 + 이메일 경보)

> **발표 스크립트**  
> "목표는 단순히 예측 정확도가 아닙니다. 실제 운영 가능한 시스템을 만드는 것이었습니다. 예측이 틀렸을 때 얼마나 빨리 감지하고 재훈련하는지, 블랙스완이 왔을 때 신뢰구간을 자동으로 넓혀서 사용자에게 경고하는지가 핵심이었습니다."

## SLIDE 08 — 개발 이력 요약 (Phase 0 → 16)

**헤드라인**: "16개 Phase, 226개 커밋, 약 4주간의 개발"

| Phase | 기간 | 핵심 변화 | 의사결정 근거 |
|-------|------|-----------|-------------|
| 0~1 | 05-07 | 초기 MVP (SARIMAX + XGBoost-HAR, 28 피처) | 빠른 기능 검증 우선 |
| 2 | 05-07~10 | 운영 인프라 (예측 로그, 이메일 알림, FRED fallback) | 안정성 없인 운영 불가 |
| 3~4 | 05-11 | Prophet 실험 후 제거, 훈련 윈도우 분리 | Prophet: 3분+ → 5분 목표 위반 |
| 5~6 | 05-12~13 | HAR 피처셋 분리, FinBERT 통합, 뉴스 다양화 | overfit_gap 0.44 → 0.08 달성 |
| 7~9 | 05-14~19 | SARIMAX 파라미터 실험, 방향성 분류기 60% | SARIMAX(0,1,0) 최적 확정 |
| 10~11 | 05-20~21 | CEEMDAN 신호 분해, Stacking + LightGBM | 앙상블 구조 완성 |
| 12~13 | 05-21~28 | 로그인·관리자 탭 구현, VAR+ETS 고도화 | 실제 사용자 구분 운영 필요 |
| 14~15 | 05-29~06-01 | 데이터 누출 수정, VaR, 블랙스완, OVX alarm | 신뢰성 없는 예측은 위험 |
| 15.5~16 | 05-25~06-02 | 운영 안정화, 다중공선성 제거, 버그 17개 수정 | 배포 전 최종 품질 점검 |

**주요 철회 결정**
- Prophet: 속도 문제 → 완전 제거
- har_vol_pred 피처: 데이터 누출 발견 → 롤백
- AR/MA 항(SARIMAX 고차수): 2026 레짐에서 노이즈 유발 → (0,1,0) 채택

> **발표 스크립트**  
> "개발은 총 16개 Phase로 진행됐습니다. 단순히 기능을 추가한 게 아니라 틀렸다고 판단되면 과감하게 롤백했습니다. Prophet 제거, 데이터 누출 수정, 다중공선성 피처 삭제가 대표적입니다. 잘못된 피처 하나가 모델 전체를 망가뜨릴 수 있기 때문에, 검증 → 채택/철회의 사이클을 엄격히 지켰습니다."

## SLIDE 10 — 성능 결과

**헤드라인**: "Persistence 대비 40% 오차 감소"

```
┌──────────────────┬────────────────────────────────────────┐
│  가격 예측        │  SARIMAX MASE  =  0.602               │
│                  │  (Persistence MASE = 1.0 기준)         │
│                  │  Stacking R²   =  0.9711               │
│                  │  Stacking MAE  =  $2.03 / bbl          │
│                  │  Max Error     =  $9.61                │
├──────────────────┼────────────────────────────────────────┤
│  변동성 예측      │  XGBoost-HAR R²      =  0.4681         │
│                  │  (훈련 overfit_gap   =  0.08)           │
├──────────────────┼────────────────────────────────────────┤
│  방향성 예측      │  In-sample Dir.Acc  =  61.1%           │
│                  │  Walk-forward Acc   =  53.6%           │
│                  │  (무작위 50% 대비 +3.6%p)              │
├──────────────────┼────────────────────────────────────────┤
│  비교 베이스라인   │  Persistence MASE   =  1.0             │
│                  │  VAR(9) MASE        =  0.9998          │
│                  │  ETS(HW-Damped)     =  1.0 수준        │
└──────────────────┴────────────────────────────────────────┘
```

**해석 포인트**
- MASE = 0.602: "오늘 가격을 그대로 쓰는 것"보다 40% 오차 감소
- Walk-forward 53.6%: 실전 조건(순서대로 예측)에서 측정, 과적합 없음
- R²=0.9711: 스태킹 앙상블이 가격 분산의 97%를 설명

> **발표 스크립트**  
> "성능을 평가할 때 저희는 단순 RMSE가 아닌 MASE를 사용했습니다. MASE=1.0은 '어제 가격을 그대로 쓰는 것'과 같은 성능입니다. 저희 MASE=0.602는 그것보다 40% 더 정확합니다. Walk-forward 방향성 53.6%는 겸손한 숫자처럼 보이지만, 순서대로 예측하는 실전 조건에서 측정된 값이고 무작위 50% 대비 일관되게 우위에 있습니다."

**시각 요소**: 막대 차트 (모델별 MASE 비교), 스태킹 R² 강조 박스

## SLIDE 11 — 핵심 기능 ①: 리스크 신호 시스템

**헤드라인**: "예측값이 아닌 '지금 당장 행동'을 알려준다"

**리스크 등급 체계**

| 등급 | 조건 | 시스템 반응 |
|------|------|-----------|
| SURGE_RISK | risk_score 高 + 상승 편향 + OVX HIGH 이상 | 이메일 즉시 발송 |
| DROP_RISK | risk_score 高 + 하락 편향 | 이메일 즉시 발송 |
| CAUTION | risk_score 중간 수준 | 대시보드 경고 표시 |
| NORMAL | risk_score 낮음 | 일반 모니터링 |

**리스크 구성 요소 (6개)**

| 지표 | 의미 |
|------|------|
| VaR(5% / 95%) | 5% 확률로 이 가격 이하로 하락 / 이상으로 상승 |
| OVX alarm | HIGH (OVX≥50) / EXTREME (OVX≥70) 레짐 |
| hedge_ratio | OVX + vol_5d 기반 헤지 비율 권고 (0~1.0) |
| surge_prob_3d | 3일 내 급등 확률 (%) |
| asymmetric_risk | downside/upside 비대칭 정도 |
| forecast_reliability | UNKNOWN → LOW → MEDIUM → HIGH |

> **발표 스크립트**  
> "예측 숫자만 보여주면 사용자가 직접 판단해야 합니다. 저희는 한 발 더 나아가 지금 어떻게 행동해야 하는지를 등급으로 알려줍니다. VaR는 최악의 경우 얼마까지 빠질 수 있는지, hedge_ratio는 얼마나 헤지해야 하는지를 자동으로 계산해서 제시합니다."

## SLIDE 12 — 핵심 기능 ②: 블랙스완 대응

**헤드라인**: "충격이 올 때 시스템도 같이 긴장한다"

```
[감지 단계]  →  [판단 단계]  →  [대응 단계]

① 관세·지정학 키워드        → jump_flag = 1      → _bs_pen 활성화
   (tariff / sanction 등)
② |수익률| > 3σ (60일 기준)  → jump_flag 확정     → CI 확대 시작
③ OPEC 긴급회의 감지         → 리스크 점수 가중   → 앙상블 가중치 조정
④ compound_shock             → 최고 경계 레벨     → CI × 2.5, 이메일 경보
   (지정학 + OPEC + 뉴스 동시)
```

**대응 상세**

| 상황 | 조치 |
|------|------|
| jump_flag = 1 (단독) | SARIMAX 앙상블 가중치 × 0.60으로 감소 |
| 관세 키워드 감지 | SARIMAX 가중치 × 0.25로 대폭 감소 |
| compound_shock | 신뢰구간 × 2.5 확대 + 이메일 즉시 발송 |
| 일반 고변동 | CI × 1.2~1.5, 방향성 임계값 완화 |

> **발표 스크립트**  
> "블랙스완은 모델이 가장 취약한 상황입니다. 과거 데이터가 없는 사건이 발생하면 모델 예측값 자체를 믿기 어렵습니다. 저희는 이때 예측을 포기하는 대신, 신뢰구간을 자동으로 넓히고 가장 안정적인 모델의 비중을 높여서 '최소한의 경보'라도 정확하게 전달하도록 설계했습니다."
